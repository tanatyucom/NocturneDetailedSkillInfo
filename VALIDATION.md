# Validation

This document records the reproducible release-audit evidence inherited from
Nocturne Detailed Skill Info v1.0.0 and the string-compatibility regression
checks added for v1.0.1.

## Canonical validation artifacts

The repository includes organized copies of the preserved release-candidate
audit data:

```text
docs/validation/skill_validation_ja.csv
docs/validation/skill_validation_en.csv
```

They were reconstructed from the preserved v1.0.0 development artifacts:

- Japanese source: `NOCTURNE_DETAILED_SKILL_INFO_RC2_AUDIT.csv`
- English source: `NOCTURNE_DETAILED_SKILL_INFO_RC4_AUDIT.csv`

Earlier RC1 / RC3 files existed during development, but the two canonical
files reproduce the final v1.0.0 counts:

| Language | Rows audited | `Changed=YES` | `Changed=NO` |
|---|---:|---:|---:|
| Japanese | 512 | 150 | 362 |
| English | 512 | 150 | 362 |

Artifact hashes:

```text

skill_validation_en.csv
```

The CSVs contain the localized official and generated help, change status,
runtime fields used by the audit, classification, and review flags. Added
metadata columns identify the language, validation scope, and whether direct
in-game verification was recorded for that row.

## What the full-table audit establishes

All 512 skill-table rows were passed through the v1.0.0 generation and
filtering logic in each supported language. A row passes when:

1. Supported numerical details are appended correctly.
2. Reserve, placeholder, internal, and excluded enemy-only rows do not receive
   false-positive detail.
3. Japanese and English suffixes follow the active localized help.
4. Verified special physical-skill corrections are retained.
5. Unsupported or unresolved raw fields remain hidden.
6. A `Changed=NO` result is preserved when no supported detail applies.

`Changed=NO` is not a failure. For excluded or unsupported rows it is the
expected result.

## What the historical audit does not establish

The CSVs do not prove that all 512 rows were individually executed in battle.
Representative skills and special cases were directly tested during
development, but the historical files did not record an in-game verification
boolean per row. The public copies therefore state:

```text
DirectInGameVerification = not recorded per-row
```

No evidence has been invented to fill that gap.

## Conservative interpretation policy

The following remain hidden unless separately validated in a future release:

- `MagicBase` and `MagicLimit`
- program-specific behavior
- unknown `HojoType` bits
- unknown or compound ailment masks
- other unresolved internal fields

The v1.0.1 compatibility fix does not reinterpret these fields or broaden the
set of eligible skills.

## v1.0.1 PASS criteria

In addition to preserving the historical generated values, v1.0.1 must pass
these string-compatibility checks:

1. When no detail is added, the original incoming help is returned exactly.
2. `<AF_DEL>`, line endings, and surrounding whitespace survive inspection.
3. Unrelated prose containing `Power:` or `威力:` is not truncated.
4. Only an exact terminal suffix previously generated by this mod for the same
   skill in the current process can be removed.
5. Repeated calls do not duplicate this mod's suffix.
6. Text produced by another Harmony patch is treated as part of the
   authoritative incoming help.

Run the dependency-free regression test with:

```powershell
dotnet run --project .\tests\SuffixPolicyRegression\SuffixPolicyRegression.csproj -c Release
```

Verify the audit artifact hashes and counts with:

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\ValidateAuditArtifacts.ps1
```

## Repeating the runtime audit

The source retains `TryExportLocalizedAudit()`. For a developer validation
build, re-enable its call in `SkillHelpGetterPatch.Postfix` without changing
the help-generation logic, then:

1. Start SMT3HD with only this mod and required loader components enabled.
2. Select Japanese and trigger a real skill-help request after localization
   tables initialize.
3. Preserve the generated audit CSV.
4. Repeat with English in a fresh process.
5. Compare row count, changed count, generated strings, classification,
   exclusions, and review flags with `docs/validation/`.
6. Investigate every difference.
7. Manually verify representative changed rows in the in-game Detailed Help UI.
8. Disable automatic export again before producing the public DLL.
